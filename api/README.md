# api

REST API and real-time (Socket.IO) gateway between the shared database and the dashboard, and the home of the database migrations for the whole stack.

- **Owner:** Damian (module C)
- **Status:** the shared schema (change `api-db-schema`) is implemented: Alembic revisions `0001` (tables) and `0002` (query indexes), and the one-shot `api-migrate` container. REST and Socket.IO come with change `api-v1`.

## What it does

- Creates the shared tables (`sources`, `documents`, `findings`, `job_errors`, `calibration_points`) with Alembic, in a one-shot `api-migrate` container that runs before the other services.
- Serves the REST API of [`contracts/openapi.yaml`](../contracts/openapi.yaml) under `/api`, behind the HTTPS gateway (`https://localhost:8443/api`) (change `api-v1`).
- Turns each finding's raw `score` into `risk_level` using the module thresholds the calibration panel sets.
- Relays live events (new findings, high-risk alerts, status changes, scan progress) to the dashboard over Socket.IO, namespace `/events`.

Why it is built this way: [ADR 0302](../.docs/decisions/0302-api-service.md) (separate Python service), [ADR 0303](../.docs/decisions/0303-database-schema-ownership.md) (migrations here), [ADR 0305](../.docs/decisions/0305-threshold-storage.md) (thresholds in Redis), [ADR 0307](../.docs/decisions/0307-database-driver-and-table-layout.md) (driver and tables).

## Tables

Columns follow `contracts/schemas/` v1; every enumerated field has a CHECK constraint with the contract's values. Times are `timestamptz` (UTC), ids are UUIDs generated by the producer.

| Table | Written by | Columns | Keys and indexes |
|---|---|---|---|
| `sources` | API (dashboard edits), scraper (`last_run_at`, `last_run_status`) | `id, name, platform, url, source_kind, target_modules text[], schedule_cron, active, last_run_at, last_run_status, created_at, updated_at` | pk `id` |
| `documents` | scraper | `id, source_id → sources, platform, source_kind, url, canonical_url, fetched_at, published_at, http_status, lang, title, text, content_hash, html_object_key, payload jsonb, stream_published_at, created_at` | unique `uq_documents_source_hash (source_id, content_hash) NULLS NOT DISTINCT WHERE content_hash IS NOT NULL`; partial `ix_documents_unpublished (created_at) WHERE stream_published_at IS NULL` |
| `findings` | analytics (upsert), API (`status`, `note`) | `id, document_id → documents (cascade), module, score, status, title, summary, firm jsonb, advertiser jsonb, rules jsonb, content_excerpt, url, platform, note, detected_at, updated_at, model jsonb` | unique `uq_findings_document_module (document_id, module)`; indexes on `detected_at DESC`, `(module, detected_at DESC)`, `status`, `platform`, `score` |
| `job_errors` | scraper | `id, source_id → sources (cascade), url, reason (non-empty), detail, occurred_at` | `(source_id, occurred_at DESC)` |
| `calibration_points` | analytics eval | `id (identity), run_id, module, threshold, tp, fp, fn, tn, precision, recall, f1, labeled_samples, computed_at` | unique `(run_id, module, threshold)`; `(module, computed_at DESC)` |

- `documents.payload` holds the nested `ScrapedDocument` fields: `author, links, media, screenshots, blocks, scrape_meta`.
- `documents.stream_published_at` is the "announced on `iw:documents`" marker. It is not the contract's `published_at` (the content's publication date).
- `findings` has no `risk_level` column: the API derives it on read ([ADR 0305](../.docs/decisions/0305-threshold-storage.md)).

## SQL the other services use

Connect as the app role (`DATABASE_URL`, `iw_app`): CRUD on every table, no DDL. Never create or alter a table from service code: ask for a new revision here.

Scraper (Adam), insert a document and drop a duplicate of the same text from the same source. Name the conflict target: a bare `ON CONFLICT DO NOTHING` would also hide a reused `id`.

```sql
INSERT INTO documents (id, source_id, platform, source_kind, url, canonical_url, fetched_at, published_at,
                       http_status, lang, title, text, content_hash, html_object_key, payload)
VALUES (...)
ON CONFLICT (source_id, content_hash) WHERE content_hash IS NOT NULL DO NOTHING
RETURNING id;          -- no row returned = same text from the same source: delete the HTML object you uploaded
```

Mark it published after `XADD iw:documents`, and the republish sweep:

```sql
UPDATE documents SET stream_published_at = now() WHERE id = $1;

SELECT id FROM documents
WHERE stream_published_at IS NULL AND created_at < now() - interval '1 minute'   -- skip rows an ingest is announcing right now
ORDER BY created_at, id LIMIT 100;
```

Job errors: `INSERT INTO job_errors (id, source_id, url, reason, detail) VALUES (...)`. `detail` never holds credentials, proxy URLs or headers.

Analytics, upsert one finding per document and module. A re-scan replaces the analysis and keeps the analyst's `status` and `note`, the original `id` and `detected_at`:

```sql
INSERT INTO findings (id, document_id, module, score, status, title, summary, firm, advertiser, rules,
                      content_excerpt, url, platform, detected_at, updated_at, model)
VALUES (...)
ON CONFLICT ON CONSTRAINT uq_findings_document_module DO UPDATE SET
  score = excluded.score, title = excluded.title, summary = excluded.summary, firm = excluded.firm,
  advertiser = excluded.advertiser, rules = excluded.rules, content_excerpt = excluded.content_excerpt,
  url = excluded.url, platform = excluded.platform, model = excluded.model, updated_at = excluded.updated_at;
```

The same statements in Python (SQLAlchemy) are in `src/investwatch_api/db/sql.py` (`document_insert_ignore_duplicate`, `unpublished_documents`, `findings_upsert`); contract dict ↔ row mapping is in `src/investwatch_api/db/mapping.py`.

## Running it

Migrations, in the stack: the root `compose.yaml` includes `api/compose.yaml`, and `api-migrate` runs `alembic upgrade head` as `iw_admin` once Postgres is healthy, then exits. A service that writes the database waits for it:

```yaml
depends_on:
  api-migrate: { condition: service_completed_successfully }
```

Locally, from `api/`:

```bash
python -m venv .venv && .venv/Scripts/pip install -r requirements-dev.txt   # Windows; bin/ on Linux/macOS
DATABASE_ADMIN_URL=postgresql://iw_admin:<password>@localhost:5432/investwatch .venv/Scripts/alembic upgrade head
```

New revision: add `migrations/versions/NNNN_<slug>.py` by hand (copy the style of `0001_initial.py`), update `src/investwatch_api/db/tables.py` to match, and run the tests: `test_models_match_the_migrations` fails if the two differ. Never edit an applied revision.

## Tests

Database tests need a real Postgres 17 (constraints like `NULLS NOT DISTINCT` and the role grants are what they check). Start a throwaway server bound to localhost only, then point the tests at it:

```bash
docker run -d --rm --name iw-test-pg -e POSTGRES_PASSWORD=test -p 127.0.0.1:55432:5432 public.ecr.aws/docker/library/postgres:17-alpine
TEST_DATABASE_ADMIN_URL=postgresql://postgres:test@127.0.0.1:55432/postgres .venv/Scripts/python -m pytest
```

Each test session creates its own `iw_test_*` databases and an `iw_test_app` role with the same grants as `infra/postgres/init/01-app-role.sh`, and drops the databases at the end. Without `TEST_DATABASE_ADMIN_URL` the database tests are skipped, not failed.
