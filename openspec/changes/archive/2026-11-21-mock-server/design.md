## Context

`contracts/` (owner Damian) holds draft v1 of the JSON Schemas, `openapi.yaml` (11 paths) and deterministic mocks generated by `contracts/mocks/generate_mocks.py`, validated by `contracts/validate.py`. The dashboard (`web/`, owner Kacper) must work against the contract before the real API exists; the API's own placement and stack are still open (ADR 0302 draft), as are the database (ADR 0303) and `docker-compose.yml` (deployment ADR). The mock server is a development and demo tool, not a prototype of the real API.

## Goals / Non-Goals

**Goals:**
- Kacper can point the dashboard at `http://localhost:8000/api` and Socket.IO `/events` today and later switch to the real API by changing nothing but the base URL.
- Every response and event is checked against the same schemas the real services will use, so the mock cannot drift from the contract unnoticed.
- Write operations and live events behave realistically enough to build the status change, alerts and the calibration slider.

**Non-Goals:**
- Persistence, authentication, rate limiting, real scans.
- Deciding the real API's stack or location (ADR 0302) or reusing this code as the real API.
- Changing any contract; if the mock needs a field the contract lacks, that is a contract change for the whole team.
- Adding the service to `docker-compose.yml` (pending deployment ADR); a Dockerfile is enough for now.

## Decisions

1. **Location: `contracts/mock-server/`.** It is derived from and tested against `contracts/`, has the same owner, and needs no new top-level directory (Kacper owns the layout). Alternative: a top-level `mock-api/` (needs Kacper's OK and a `CLAUDE.md`), or inside `web/` (Kacper's directory, couples the mock to one consumer).
2. **Stack: Python 3.13, FastAPI + python-socketio (ASGI app mounted together), uvicorn.** The contract tooling is already Python (`validate.py`, the generator), FastAPI gives 422 validation for query/body parameters for free, and python-socketio speaks the same protocol as the `socket.io-client` the dashboard will use. Alternatives: Prism (OpenAPI-driven mock, but no Socket.IO and no state), json-server (no Socket.IO, does not follow `openapi.yaml`), MSW in the browser (Kacper's choice inside `web/`, does not exercise real HTTP/WS and cannot be used by other teammates or in a demo).
3. **Data source: the existing mock files, loaded and schema-validated at start-up, then deep-copied into an in-memory store.** No second copy of the data; regenerating mocks with the generator updates the server. Invalid data fails fast (spec: broken mock data).
4. **`risk_level` computed at read time** from `score` and the current thresholds, exactly as the API is planned to do ([`analytics/CLAUDE.md`](../../../analytics/CLAUDE.md), ADR 0305 draft option 3). This keeps the mock neutral to the 0305 decision: the dashboard sees the same Socket.IO events whichever option is chosen.
5. **Replay instead of scripted sequences.** A background task clones a random mock finding every N seconds (env `MOCK_REPLAY_INTERVAL_S`, `0` disables) so alerts and the trend chart move without any other service. `POST /__mock/emit` triggers one replay on demand for tests and demos.
6. **Mock-only routes under `/__mock/`** (`reset`, `emit`) so they can never be confused with contract routes and the dashboard never calls them.
7. **Configuration by env only** (`MOCK_PORT`, `MOCK_CORS_ORIGINS`, `MOCK_REPLAY_INTERVAL_S`, `MOCK_SCAN_DELAY_S`, `CONTRACTS_DIR`), following the convention in `.docs/integration-plan.md` §7. `CONTRACTS_DIR` defaults to the parent `contracts/` directory so the server works from a plain checkout and in Docker.

None of these choices is hard to reverse (the whole directory can be deleted once the real API exists), so no ADR draft is needed.

## Risks / Trade-offs

- [The mock behaves differently from the real API on edge cases (sorting ties, search semantics)] → keep behaviour to what the spec states, and add the same spec scenarios as tests to the real API change later.
- [Kacper builds on mock-only behaviour such as replay timing] → replay and `/__mock/` are documented as development aids; the dashboard must work with replay disabled.
- [Contract changes leave the mock stale] → start-up validation and the test suite run the schemas, so a stale mock fails loudly; the contracts `CLAUDE.md` already requires updating consumers in the same PR.
- [Dependencies add vulnerabilities] → pinned versions, `pip-audit` before merge, results noted in the PR body.
- [Port 8000 clashes with the real API when both run] → port is configurable; document running one at a time.
