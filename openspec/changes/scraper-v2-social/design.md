# Design

## Context

`scraper-v1` fetches one URL and parses it into one `ParsedPage` through a registry keyed by host. `scraper-orchestration` adds `run_source` (`collect.py`), which joins guards, robots, fetch, parse and `Ingestor.ingest(page, source, ...)`. A Telegram channel page holds up to 20 posts, so one fetch yields many documents and one run may need several fetches. The research on 2026-11-21 (scratchpad samples of 12 channel pages and a `?before=2000` page, taken with our `noble-tls` identity, about 5 s apart) found: HTTP 200 and 100 to 160 KB of server-rendered HTML, no `robots.txt` (404, so allowed), no 429 in about 25 requests.

## Decisions

1. **A collector registry beside the parser registry.** `PageParser` returns one `ParsedPage`, which cannot express "many posts plus a next page". A second registry, `social.registry`, maps host to a collector module with `parse(body, final_url) -> Channel` (header plus posts plus the `before` link). It copies the registry's rules (key by host with `www.` equivalence, refuse duplicates) and registers the one `platform` it accepts for the host (`other` for Telegram), which `Source.collectable` checks. The neutral result types (`Channel` with `network` and `profile_url`, `Post`, `Link`) and the page-dict builder live in `social/model.py`; a platform module holds only its parser, so a second platform imports nothing from the Telegram module. `run_source` asks it first when `source.platform != "web"`. Rejected: widening `ParsedPage` for every site.
2. **`Source.collectable` is `active and (platform == "web" or a collector accepts the host)`.** `collectable` is a no-argument property on the frozen `Source` that `select_sources`, `UrlGuard.for_sources` and `run_source` all call, so the host set cannot be passed in: it reads `social.registry`'s hosts from a leaf module that imports nothing from `types`, and no caller changes. No `FETCH_EXTRA_HOSTS` entry is needed, because the allow-list is built from the hosts of collectable sources (`UrlGuard.for_sources`) and a Telegram source puts `t.me` on it. A source whose redirect leaves `t.me` is refused by the existing guard.
3. **`platform = other`.** The contract v1 enum has no `telegram` and is frozen. `other` is the only honest value. Telling Telegram sources apart is by host, not by platform. A `telegram` value is a contract v2 change for the whole team, agreed in principle by Damian on issue #34 and scheduled after the hackathon.
4. **Per-post HTML.** `iw-raw` holds the markup of the one message wrapper (a few KB), not the 100 to 160 KB page copied 20 times. The source of the `ingest` page dict's `html` is the serialised wrapper.
5. **Stateless paging.** No stored cursor, so no schema change. A run reads the newest page, then `?before=<id>` from the page's `tme_messages_more` link, up to `SOCIAL_MAX_POSTS` (default 40, two pages). It stops early when every post that has text on a page returns `duplicate` from ingest, which makes a rerun of a quiet channel cost one request.
6. **A social document's identity includes its permalink.** The challenge asks for "the exact location (URL)" of each ad, and the dedup index is `(source_id, content_hash)`, so a promo reposted verbatim in one channel would collapse into the first post and lose a location. Read on `origin/main`: `scraped-document.schema.json` describes `content_hash` as "sha256 of the normalized text" with only a hex pattern; `ck_documents_content_hash` and `uq_documents_source_hash` check the shape and the pair, not the input; `ingest/document.py` derives the hash itself and never trusts the page; analytics computes its own hash in `preprocessing.py` and the API only passes the column through. So for `platform != web` the ingest hashes `(canonical_url or url) + "\n" + normalised text` (Damian's adjustment on issue #34: share and tracking parameters must not change the hash; Telegram sets `canonical_url` equal to the permalink): no schema, migration, index or contract-schema change. This is a MODIFIED requirement of `document-ingest` in this change, and it stretches the wording of a frozen contract description, which Damian accepted on 2026-11-21 on condition that the description is updated together with the #31 decision (task 5.1). Rejected: a second column or index (Damian's schema, a migration); dropping the dedup for social (a rerun would insert every post again). An edited post still gets a new row, as before.
7. **Links are data.** Anchors and bare URLs go to `links` as `{href, text}`. `x.com` and YouTube links are pointers for analytics and reviewers; the collector never requests them (the guard would refuse them anyway, as they are not allow-listed hosts).
8. **Followers.** `36.1K` is 36100 and `1.2M` is 1200000; the value is rounded to the nearest integer. The counter is an approximation shown by Telegram, which is what the contract's `followers` carries for other platforms too.
9. **Selectors** (from the saved pages): message wrapper `tgme_widget_message_wrap`; id from `data-post` (`<handle>/<id>`); text `tgme_widget_message_text` (not the reply preview); time `<time datetime>`; permalink `tgme_widget_message_date` href; views `tgme_widget_message_views`; header `tgme_channel_info_header_title`, `..._username`, `tgme_channel_info_counters`; older posts `a.tme_messages_more`. A change of Telegram's markup shows up as `parse_error` (no header and no posts), not as empty documents.
10. **Failures reuse the closed reasons** of `web-collection`: nothing new is added. "No public preview" is `parse_error` with that detail, "wrong URL form" is `invalid_request`.

11. **Same fetch path as web (UA and proxy rotation).** The brief asks for user-agent and proxy rotation in social collectors. The collector therefore has no HTTP client of its own: every page goes through `fetch`, robots, the per-domain limiter and the URL guards of `scraper-v1`/`scraper-orchestration`, with one identity drawn per run and a proxy picked per request. A page-level test with a recording stub proves it (task 2.1).
12. **`scrape_meta` extras are allowed.** Verified in `scraped-document.schema.json`: `scrape_meta` has `additionalProperties: true`, so `message_id` and `views` need no contract change. `views` is kept as an engagement signal for ranking. `network` (`"telegram"`) is added too, as Damian suggested on issue #34: it is the only marker of the real network while `platform = other`, and a later backfill to a `telegram` platform value can key on it.
13. **Seeds.** The Telegram `sources` rows are this change's, added through the seed mechanism of `scraper-orchestration` (`seed.py`: URL absent, never overwrite). They live in `scraper/seeds/telegram.toml`, read by the loader of `scraper-v2-sources` (its decision 1, as revised in its commit `0fad0fd`: `load_seed(path)` validates one TOML file, `seed_sources(pool, entries)` writes, and `main` loads every `*.toml` in `scraper/seeds/`, validates the combined list once, then writes; a URL repeated across files is a duplicate; `platform` accepts any contract value, default `web`, and its own `sources.toml` is asserted all `web`). So `telegram.toml` needs only the file and its test, with no loader edit and no second call in `main`. This change does not redefine the loader. If `scraper-v2-sources` is not merged yet, the same rows are written with the `seed_knf` insert pattern and moved at rebase. Rows (cron UTC, staggered one domain, `platform = other`): `rarecryptosignals` M1 `third_party` (exchange bonus and referral promotion), `crypto_sygnaly` M3 `unknown` (VIP signal teasers), `SubeTradingPL` M3 `unknown` (trading calls), `kdpwiadomosci` M1 `third_party` as a neutral news control. `unknown` because the scraper cannot know registry status (analytics routes M3 by registry mismatch); it is in the contract enum and the `ck_sources_source_kind` check. Each row is a candidate that matches a signal, never a finding about the channel.

## Fit to the challenge brief

The brief (`doc/Opis Wyzwania HackNation UKNF 19.11.pdf`) asks for a collector layer with user-agent and proxy rotation "for social media" and names Facebook, Instagram and TikTok as examples ("m.in."). It is judged on scraping effectiveness, architecture ("composition of modules, scalability, openness to extension", 20%), fit to the specification (20%), the safety of the libraries used and the absence of `console.log`.

| Brief | This change |
|---|---|
| Module 1 result: advertiser data, ad content, exact URL, periodic update | `author` from the channel header, `text`, one permalink per post (identity includes it), cron seed rows with dedup on rerun |
| UA and proxy rotation in social collectors | the shared fetch path, decision 11, proven by a recording stub (task 2.1a) |
| Facebook, Instagram, TikTok | **not covered**: login walls and a JS shell on 2026-11-21 (ADR 0103 holds the evidence). Telegram is the one platform that answers an anonymous, robots-allowed request with post text. Each missing platform is a new module under `social/`, one registration and a `sources` row |
| Lightweight modules, open for extension | collector registry by host, platform-neutral `social/model.py`, no change to `run_source`, ingest or the contract to add a platform |
| Dependencies scanned, no `console.log` | no new dependency; logger only |
| Process with AI assistants documented | the OpenSpec change, the commit cycle and the AI log row (task 5.1) |

Long-term upkeep: Telegram's markup is not a contract, so a change shows up as `parse_error` (decision 9) and the opt-in live smoke test (task 3.2) is the canary; the saved pages in `tests/fixtures/` are the regression set. The recipe for the next platform goes into `scraper/CLAUDE.md` (task 5.1).

## Extension point: the collector registry

`social.registry` maps a host to a collector module `parse(body, final_url) -> Channel`, and `Source.collectable` accepts a non-web source when a collector exists for its host. A later platform (YouTube through the Data API, for instance) is a new module under `social/`, one registration and a `sources` row, with no change to `run_source`, ingest or the contract. Collectors that call an API instead of a page implement the same shape behind the same fetch layer; adding one is its own change with its own terms check. Nothing but the Telegram collector is built here.

## Follow-up (not in this change): a `telegram` platform value

`platform = other` makes Telegram posts show up as "other" in the dashboard filters. The proper fix is a `telegram` value in the `platform` enum: `contracts/schemas`, `contracts/openapi.yaml`, the generated client and the `web/` filter labels. That is a contract change for the whole team under the freeze. Damian agrees to add it after the hackathon (issue #34), and counts ten hard-coded places, one of them a database CHECK constraint that needs an Alembic migration: three contract schemas, `openapi.yaml`, the mock server, the analytics and API models, `db/tables.py`, migration 0001 and the generated web client. This change edits no contract and works unchanged with `other`.

## ADR

ADR 0103 is written in the docs task as accepted: context, the options with this evidence (X: `robots.txt` `User-agent: * / Disallow: /`, the syndication timeline 429, `api.x.com` 401, official API pay-per-use at $0.005 per post read; Facebook and Instagram: 200 login-wall shells; TikTok: a 409 KB JavaScript shell with `statusCode 10221`; YouTube: `/feeds/videos.xml` disallowed by `robots.txt`, channel pages redirect to a consent page, oEmbed gives title and author only; Wykop: server-rendered but weak for M1; Telegram: the findings above), the decision (Telegram, decided by the human on 2026-11-21) and the consequences. X and YouTube stay later options: X only through a paid API with an exception ADR, YouTube through the Data API v3 as an optional later change (terms and quota not checked).

## Risks

- Telegram's terms for on-premise collection of public channels were not researched. Only the public preview is read, politely, with no login.
- Channels can switch the preview off, VIP content is unreachable, and the preview may show fewer posts than the channel has.
- A run is up to three requests (`robots.txt` and two pages) spaced by the per-domain limiter, and they must fit the queue's `SCRAPER_ATTEMPT_TIMEOUT` (60 s by default). With very slow answers the second page can be cut off and the attempt retried; the retry is safe because stored posts are duplicates. A block on a later page after documents were stored is a `partial` run, which the queue counts as healthy for the domain (its rule, not changed here).
- The older-posts link comes from the page, so it is followed only when it is `https://t.me/s/<the same handle>?before=<digits>`; anything else ends paging.
- Post text and authorship are untrusted input: stored as text, never rendered as HTML downstream by this module.
- Whether the seed channels contain content that violates the challenge's rules was not reviewed; they are inputs, not findings.

## Open questions

1. **Settled (Damian, issue #34, 2026-11-21):** hashing `(canonical_url or url) + "\n" + text` for `platform != web` is acceptable. His condition: the description of `content_hash` in `scraped-document.schema.json` (line 26) and `.docs/integration-plan.md` §3 (line 84) is reworded to `platform == web`: sha256(norm(text)), otherwise sha256(canonical_url_or_url + "\n" + norm(text)), landing with the #31 decision (NFC vs NFKC, where ingest's NFC is canonical) so the definition is written once. That edit is description-only but touches a frozen contract file: it needs `IW_CONTRACT_CHANGE=1`, which only the human may approve (task 5.1).
2. **Loader (settled, no action):** `scraper-v2-sources` (`0fad0fd`) loads every `*.toml` in `scraper/seeds/` and accepts any contract `platform`, so `telegram.toml` needs no loader change. If it is not merged first, task 4.1 uses the `seed_knf` insert pattern and is moved at rebase. `scraper-v2-sources` must not seed the Telegram channels (this change owns them).
