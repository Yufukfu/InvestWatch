# Design

## Context

- `scraper-v1` fetches with `noble-tls` (ADR 0101) and parses with `lxml`; `scraper-ingest` stores the raw HTML at `html/{id}.html` before the insert and removes it when the insert certainly did not commit (`ingest/pipeline.py`); `scraper-orchestration` adds `run_source`, the run that joins guards, fetch, parse and ingest. Playwright is the last rung of the ladder (`iw-scraper-conventions`).
- Contract (v1, `contracts/schemas/scraped-document.schema.json`): `screenshots` is `{desktop, tablet, mobile}` of object keys or null; `blocks` is a list of `block` (required `viewport, text, font_size_px, visible`; optional `tag, font_weight, color, background_color, bbox, in_viewport_on_load, requires_interaction, region, overflow_clipped`); `scrape_meta` accepts extra keys. `analytics/` declares `blocks` in its model but nothing consumes it yet; `api/` already serves `GET /documents/{id}/screenshot/{viewport}` from the `documents.payload.screenshots` key.
- `sources` has no config column and `source.schema.json` has `additionalProperties: false`: no per-source setting can be stored without a contract change and an Alembic revision (Damian).
- Error reasons: the closed set is the `Reason` `StrEnum` in `scraper/src/iw_scraper/types.py` and the `web-collection` requirement "Use one closed set of job error reasons". In the database `job_errors.reason` is `Text NOT NULL` with only `ck_job_errors_reason_not_empty` (`api/migrations/versions/0001_initial.py`); no schema in `contracts/`, `api/`, `analytics/` or `web/` lists the reasons (grep of `blocked_target`, `publish_failed` finds only ADR 0104). A new reason is therefore a scraper-side change.
- Identities (`identities.py` on `origin/main`): the table holds three desktop Chrome entries (Windows, macOS, Linux; `sec-ch-ua-mobile: ?0`) built by one `_chrome` helper from `CHROME_VERSION` (146); `check_pairing` verifies that the user agent family and version, `sec-ch-ua` and the TLS profile are one browser version, and a run draws one identity.
- The scraper runtime image is 254 MB (`iw-scraper:rt`, measured locally); the latest `playwright` on PyPI is 1.60.0 (`pip index versions playwright`, 2026-11-21); Microsoft publishes `mcr.microsoft.com/playwright/python` images. The Chromium and system-library size is not measured yet; task 1.1 measures it and ADR 0105 records it.
- Network model (`infra/README.md`): `data` is internal (Postgres, Redis, MinIO), `egress` reaches the internet; a module may declare its own private network in its compose file.
- Demo set for the visual rules: XTB IKE and IKZE pages and the mBank IKE pages, static HTML of 300-600 KB whose layout cannot be recovered from text (research by the sources probe, 2026-11-21).

## Goals / Non-Goals

**Goals:**
- Deliver `blocks` and `screenshots` for the demo pages so R4-R8 and R13 can run on real material.
- Keep the browser, which executes hostile page code, away from every secret and every internal service.
- Keep the text pipeline unchanged: a render problem must never lose or change a document.

**Non-Goals:**
- Rendering as a fallback for JS-only pages or bot walls (a different reason to use the last rung; not needed for the demo).
- Pixel analysis, OCR, or judging the rules (analytics' job).
- A per-source render switch or any `sources` column (a post-hackathon proposal for Damian) and rendering social posts.

## Decisions

1. **Separate renderer image and service, scraper stays Playwright-free.** Options: (A) Playwright and Chromium inside the scraper image: one image, simple calls, but the browser then runs next to `DATABASE_URL`, `REDIS_URL` and `MINIO_*` and grows a 254 MB image by the browser and its libraries. (B) a separate image with a small HTTP service the scraper calls: the browser holds no secrets, own base image and update cadence, own limits. (C) a separate arq worker on a `render` queue: needs `REDIS_URL` in the browser container, which is exactly what we avoid. Decision: B, recorded as ADR 0105 with the measured sizes (task 1.1). The renderer lives in the scraper's directory (`scraper/src/iw_renderer/`, its own image target; no new top-level directory). It gets one `POST /render` per viewport (`target`, viewport name, the identity for that viewport, proxy, deadline) and returns JSON with that viewport's blocks and a base64 PNG; the scraper calls it up to three times, so it can pace each navigation (decision 3), and uploads to MinIO and inserts. The proxy URL travels only in the request body over the private network, is never logged, and is not stored.
2. **Hook, not a rewrite of the run.** `run_source` (`collect.py`, `scraper-orchestration`) hands `Ingestor.ingest` a `document` dict. When the source qualifies (`firm_own`, `M2`, decision 8), it adds `document["render"]`: an async callable (not a result), and `render` joins `_PAGE_ONLY_KEYS` in `ingest/document.py` so it never leaks into the stored document. Ingest awaits it only after the duplicate check, so an unchanged page costs no browser time and no budget (rendering before ingest would burn three navigations on every rescan of a page that is then discarded as a duplicate). Ingest then uploads the PNGs next to the HTML, sets `screenshots`, `blocks` and `scrape_meta.render` before validation, records render errors with its own redacting `_record`, and cleans up on duplicate or failed insert exactly as it does for HTML (the single-key discard becomes a list). The one hook in `run_source` and the extension of `Ingestor` are the only edits to orchestration and ingest code; both are additive and gated by `page.get("render")`.
3. **Guards split by who owns the state.** The scraper owns `robots.txt`, the per-domain rate limit, `Retry-After`, failure pause and identity draw (Redis state, run context). `robots.txt` was already checked by `run_source` before the page was fetched (a refusal ends the run with no document, so render never sees it); before each viewport call the scraper takes `limiter.wait_turn(domain)` and checks `DomainGate`, and a `Retry-After` from a render 403 or 429 goes to `DomainGate.defer_for_retry_after`. That is why the renderer is called once per viewport and not once per document. The renderer is stateless and enforces confinement inside the browser with the `AddressGuard` check plus its own scheme, port and navigation rules (the source host and ports come per call). It does not use `UrlGuard`'s host list, which would refuse the CDN hosts that third-party styles and fonts need. `iw_scraper.targets` imports `iw_scraper.fetch` (and so `noble_tls`), so task 2.2 first moves the pure address checks into a module without that dependency, re-exported from `targets` so nothing else changes; if that split is not a plain move, the renderer image installs the scraper's import dependencies instead (verify that `import noble_tls` needs no downloaded library). Tests inject a resolver or `internal_hosts` so a local fixture server passes, as in the fetch tests.
4. **Real device emulation: one fresh context and one navigation per viewport.** Rule R8 is about how the page looks on other screens, so each viewport gets its own Playwright context with `viewport`, `device_scale_factor` 1, `has_touch` and `is_mobile` (the latter makes the browser honour `<meta name="viewport">`, which resizing one page never does) and its own User-Agent, then waits for layout to settle and measures, in the order `desktop`, `mobile`, `tablet`. Cost: three page loads per document, each passing the per-domain rate limit and the domain gate as its own request (about 10 s of politeness delay per document with the default 5 s spacing); with a handful of M2 pages a day this is negligible, and a site that serves different markup by User-Agent is measured correctly. **Identity per viewport** keeps the "one identity unit" rule of `iw-scraper-conventions`: the run draws one identity as today, `desktop` and `tablet` use it (a tablet asks for the desktop site, as iPadOS does, with touch on), and `mobile` uses `mobile_variant(identity)`, a new helper next to `_chrome` that builds an Android Chrome entry of the same Chrome version (`Mozilla/5.0 (Linux; Android 10; K) ... Chrome/146.0.0.0 Mobile Safari/537.36`, `sec-ch-ua-mobile: ?1`, `sec-ch-ua-platform: "Android"`); the variant of every table entry is built and passed through `check_pairing` at import, so a mismatched mobile identity stops the process like any other. Playwright's Chromium sends its own real TLS handshake, so the table's TLS profile is not applied here; the identity must therefore not claim a version the pinned browser is not: task 1.1 picks the Playwright release whose bundled Chromium major equals `CHROME_VERSION` (not simply the latest release) and the renderer refuses a request whose identity major differs from its browser's, reported by `/health`. If no release matches, the fallback is that the renderer builds the user agent and hints from the browser's own version for all viewports (`mobile_variant` takes the version as a parameter), recorded in ADR 0105. `CHROME_VERSION` is not bumped here: a new value also needs a `noble-tls` TLS profile for it, which belongs to the fetch layer. A block signal in any viewport ends the render; viewports not yet loaded are not attempted.
5. **Measure in the page with one script, text stays verbatim.** A single `page.evaluate` script walks the DOM once per viewport, takes the nearest block-level element that owns text, reads `getComputedStyle` and `getBoundingClientRect`, composites alpha colours over the nearest opaque ancestor background (`null` when it is an image or gradient), and classifies `visible`, `requires_interaction` and `region` with the rules in the spec. Heuristics for `legal` and interaction are word and attribute lists in one module so they are testable and extendable; footnote markers (`*`, `¹`) stay a text decision for analytics (R6 reads the text), not a flag here. The script is a small `.js` file in the renderer package, without `console.log`.
6. **`text` stays the static parse.** The render supplies layout, not content, so `content_hash` and dedup behave as before and a flaky browser can never change what counts as a changed page. Cost: JS-injected text is absent from `text` while present in `blocks`; the demo pages are static.
7. **Failures degrade, with one dedicated reason.** The document is ingested without `blocks` and `screenshots` and a job error is recorded: `blocked` for a block signal, `blocked_target` for a refused target, `storage_error` for an upload failure, and the new `render_failed` for everything else (browser crash, timeout, renderer unreachable, malformed renderer response, a viewport that could not be captured), with a plain detail naming the cause and no `render:` prefix or URL query. Why a new reason and not `timeout`: the queue retries `timeout` and 5xx and a failed domain outcome starts a cooldown (`scraper-orchestration`), neither of which should follow a broken browser after the text document was stored. Evidence that the reason is scraper-side only is in Context. The delta is a MODIFIED "Use one closed set of job error reasons" in `specs/web-collection/spec.md`; the other changes in flight do not touch that requirement (`scraper-orchestration` adds the `scan-orchestration` capability and records existing reasons, `scraper-v2-social` modifies "Collect active sources only"). If the base spec changes before archive, the delta is re-applied on the new text.
8. **Render by domain rule, bounded by two settings.** The visual rules apply to a firm's own marketing page, so the trigger is data the source already has: `source_kind = firm_own` and `target_modules` containing `M2`. No flag on the source (a contract change plus a migration), no host list in the environment (it would drift from the dashboard-editable `sources` table). `SCRAPER_RENDER_ENABLED` is the kill switch (default `false` in code so a scraper started without the renderer does not fail, `true` in the stack's `.env.example`). `SCRAPER_RENDER_MAX_PER_HOUR` (default 20) is one budget shared by all workers through a Redis counter keyed by the UTC hour (`iw:scraper:render:<YYYYMMDDHH>` with a TTL, taken when a render actually starts, after the duplicate check); a run renders at most its one page by construction, so the budget is the useful cap. Settings read from the environment as booleans need explicit parsing: `from_env` would turn the string `false` into `True`. When it is spent the render is skipped, the document is ingested without layout, `scrape_meta.render.skipped` is `budget` and no job error is recorded. `scraper-v2-sources` seeds the XTB and mBank rows as `firm_own` + `M2` and sets nothing for rendering. A future `sources.config` column (per-source render switch and parser options) is a post-hackathon proposal for Damian, not part of this change.
9. **Viewport names and sizes** follow the contract enum (`desktop`, `tablet`, `mobile`) and are constants in one module: 1440x900, 820x1180 and 390x844 CSS pixels, device scale factor 1 for all three (layout in CSS pixels does not depend on it, and PNGs stay under `RENDER_MAX_PNG_BYTES`); `is_mobile` and `has_touch` on for `mobile`, `has_touch` on for `tablet`.
10. **Order of delivery.** Each step leaves something demonstrable if time runs out. First the confined browser and the `desktop` and `mobile` screenshots, the renderer service and the wiring into the run and ingest (the dashboard's screenshot route in `api/` then shows real pages). Second the `blocks` measurement for those two viewports (R4-R8, R13 become judgeable). Last the `tablet` viewport (`screenshots.tablet` stays `null`, which the contract allows), and the end-to-end and docs closing. The `tasks.md` groups follow this order.
11. **Hardening of the container**: non-root user, read-only root filesystem with a tmpfs for the browser's profile and `/tmp`, `no-new-privileges`, `cap_drop: [ALL]`, CPU and memory limits, `shm_size` for Chromium, fresh browser context per render, `Accept-Language: pl-PL`. Docker's default seccomp profile blocks the user namespaces Chromium's sandbox needs, so whether the sandbox starts under these settings is measured in task 1.1. Options: a seccomp profile that allows them (Playwright documents one) or `--no-sandbox`; `--no-sandbox` is acceptable only because the container holds no secrets, sits on no `data` network, and the choice is written into ADR 0105. Browser-side confinement uses Playwright's own switches: `service_workers="block"`, `accept_downloads=False`, no granted permissions, popups closed, dialogs dismissed, and websockets closed through `route_web_socket` (`route` does not see them).

## Risks / Trade-offs

- **DNS rebinding between our check and Chromium's own resolution.** Playwright cannot pin the resolved address per request like our TLS client does. The request check reduces it; the container has no secrets and no `data` network. Residual risk recorded in ADR 0105.
- **Reachability.** The `egress` network is shared with the scraper, analytics and `ollama-pull`, so the renderer's port is reachable from those peers as well as from the scraper; the browser reaching them is stopped by the private-address check, not by the network. With a run proxy, the proxy (not the renderer) resolves names, so the address check is advisory there. Both recorded in ADR 0105.
- **Attempt timeout.** `run_source` runs inside `QueueSettings.attempt_timeout` (`SCRAPER_ATTEMPT_TIMEOUT`, default 60 s), shorter than `RENDER_TIMEOUT_SECONDS` (90 s) plus the fetch and the politeness delays; an unadjusted run would end as a retried `timeout` after the document was lost. Task 4.1 sets the attempt timeout in `.env.example` and refuses to start with render enabled when it is shorter than the render timeout plus 60 s.
- **Image size and build time** (browser download): a hardware-requirements line in the README, and the image builds only with the stack's render service. Mitigation: the browser build is pinned and checksum-verified, built once.
- **Layout heuristics are heuristics** (`legal`, `requires_interaction`, colour of images and gradients). Wrong guesses are made visible with tests on small synthetic pages per rule, and `null` is preferred to a guess.
- **Payload size**: three viewports of up to 600 blocks each is hundreds of KB in `documents.payload` (JSONB, TOASTed). Caps are env settings and `truncated` is reported; the effect on the API's `GET /findings/{id}` response is checked in the end-to-end task.
- **Time**: Playwright, Chromium and the confinement are the largest single piece of scraper work left. The order of delivery (decision 10) is the mitigation: after groups 1-4 there are real desktop and mobile screenshots in the stack; group 5 adds `blocks`; the tablet viewport (group 6) is the first thing to drop. If even group 5 is cut, the visual rules stay `not_applicable` as they are today.
- **Three loads per document** instead of one: more requests to a firm's site (still under the domain's rate limit and the hourly budget) and a longer render (default timeout 90 s for the whole render). Accepted for a correct R8.
- **Chromium major vs identity table**: the pinned browser's version may differ from `CHROME_VERSION`; decision 4 says what happens, task 1.1 measures it.

## Open Questions

1. **Occlusion (contract, Damian), deferred.** R5 includes "przesłonięcie przez inne elementy", and `block` has no field for it. Proposed shape: optional `occluded: boolean | null` ("another element, such as a sticky bar, banner or overlay, covers the block's centre point"; null = not measured), measured with `document.elementFromPoint`. After Integration #1 this needs the whole team and a version bump (`IW_CONTRACT_CHANGE=1`); until then `region: overlay` is the only hint. Damian agreed on 2026-11-21 (issue #34): ship without it; R5 is not implemented in analytics yet and will treat "covered" as not measured, never as a pass. Nothing else waits for it and it is not a done criterion of this change (tasks, "Deferred follow-up").
2. **`legal` word list: answered by Damian (issue #34, 2026-11-21), folded into the spec.** R6 fails a risk block whose region is `footer` or `legal` and that is not in the viewport on load, and passes one in `main` or `aside`, so the list is analytics' recall. Placement words only, never content words (`risk`, `ryzyk`, `ostrzezen`, `warning`): a prominent risk box below the fold would otherwise become `legal` and fail R6 though it is not hidden. `region` is always set, `main` by default, never `null`, because R6 can never pass an unknown region. Footnote markers (`*`, `¹`) stay with analytics. Structural hints (`small`, `role=note`, `role=doc-footnote`, `role=doc-endnotes`) join the word list. The words are substring matches and broad ones (`terms`, `notice`, `prawn`) can over-match; the synthetic-page tests of task 5.3 pin the cases, and further words are added there.
3. **Per-source behaviour as data (Damian, after the hackathon).** A `sources.config` column (render switch, parser options) would need the contract, an Alembic revision and the dashboard's source form. Not proposed here; decision 8 makes it unnecessary for the demo.
4. **Chromium major vs `CHROME_VERSION`: measured (task 1.1, ADR 0105).** No Playwright release bundles Chromium 146 (1.58.0 has 145, 1.59.0 has 147), so the decision 4 fallback applies: pin `playwright==1.59.0` and build the user agent and hints from the browser's own version. The Chromium sandbox does not start under Docker's default seccomp profile, so the renderer runs with `--no-sandbox` inside the secret-free container; image size 360 MB.

Closed in this revision: mobile handling (real emulation, decision 4) and the render failure reason (`render_failed`, decision 7).
