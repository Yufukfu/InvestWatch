# 0201. Dashboard stack and contract-generated API client

- Status: accepted
- Date: 2026-11-21
- Deciders: agent-written; accepted by Kacper via PR

## Context

The dashboard (`web/`, owner Kacper) must build against mocks from the start and switch to the live `api` with no component changes (`web/CLAUDE.md`). The REST contract is `contracts/openapi.yaml` (owner Damian, frozen after Sat 14:30). Hand-written request code drifts from the contract silently; the team has three people and ~20 hours, so the stack must be mainstream and fast to iterate. Kacper asked for a client generated from the backend's OpenAPI file (axios or RTK).

## Options considered

1. **Vite + React + RTK Query, client generated by `@rtk-query/codegen-openapi`** (v2.2.0). Checked: it generates 23 typed hooks (`useGetFindingsQuery`, `usePatchFindingsByIdMutation`, …) from the bundled spec; RTK Query gives caching, polling and tag invalidation that the alerts and status-change features need.
2. **orval / openapi-typescript + axios.** Generates typed axios functions; caching, polling and cache invalidation would have to be added (React Query or hand-written), one more library to learn.
3. **Hand-written fetch + shared TS types.** No tooling, but every contract change is a manual edit in two places.

Mocks: **MSW** (v3) serving the contract mocks at the network layer, versus a fake data layer inside components. MSW keeps components unaware of mocks; the same handlers serve the Vitest tests.

## Decision

Option 1. `web/` uses Vite, React 19, TypeScript, Redux Toolkit with RTK Query, and a client generated from the OpenAPI contract; MSW serves `contracts/mocks` in dev (`VITE_USE_MOCKS=true`) and in tests.

The contract is consumed as a **committed snapshot** (`web/src/api/openapi.json`, `web/src/mocks/fixtures/`, `web/src/api/generated.ts`) produced by `npm run api:generate`. `web/` therefore builds and deploys on its own (its Docker build context is `web/` only), and `npm run contracts:check` fails when the snapshot falls behind `contracts/`, so drift is visible instead of silent. Generation from a live `/openapi.json` of the FastAPI service is rejected for now: the spec file in `contracts/` is the agreed source of truth, and the build must not depend on a running backend.

## Consequences

- Contract changes reach the UI as one command plus a reviewable diff of `generated.ts`; type errors show which components break.
- Two copies of the contract exist (source in `contracts/`, snapshot in `web/`); `contracts:check` must run before merging (it is in the `web` tests).
- If Damian later generates `openapi.yaml` from FastAPI, nothing in `web/` changes: the snapshot is taken from whatever file `contracts/` holds.
- Socket.IO events are outside OpenAPI; their client is typed by hand from `contracts/schemas/events.schema.json` (later change).
