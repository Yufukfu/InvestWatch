# 0307. Database driver and table layout

- Status: accepted
- Date: 2026-11-21
- Deciders: agent-written for Damian (change `api-db-schema`); accepted by: pending approval of the PR

## Context

[ADR 0303](0303-database-schema-ownership.md) puts every migration in Alembic under `api/`, and [ADR 0302](0302-api-service.md) makes `api/` a FastAPI service. Two choices follow that are hard to change once the scraper and analytics write rows: which Postgres driver the API and Alembic use, and how the v1 contracts ([integration-plan.md](../integration-plan.md) §3-§4, `contracts/schemas/`) map onto tables. §3 already says "simple columns + `payload JSONB` for the rest" for `documents`. The scraper needs a dedup rule and a published marker (`openspec/changes/scraper-v1/design.md`), and analytics needs an upsert key so re-scans do not duplicate findings. Postgres is 17 (`infra/compose.yaml`), which supports `UNIQUE NULLS NOT DISTINCT` (added in Postgres 15).

Package versions on PyPI at the time of writing (`pip index versions`, 2026-11-21): SQLAlchemy 2.1.9, Alembic 1.20.1, psycopg 3.3.9, asyncpg 0.32.0.

## Options considered

Driver:

1. **psycopg 3 for both Alembic and the API** (`postgresql+psycopg://`). SQLAlchemy 2 has a psycopg dialect that works sync and async, so one package and one URL scheme cover migrations (sync) and the API (async).
2. **asyncpg for the API, psycopg for Alembic.** asyncpg is the usual async choice, but Alembic still needs a sync driver (or an async `env.py`), so the project carries two drivers and two URL forms.
3. **psycopg 2.** Sync only; the API would run queries in a thread pool.

Table layout:

1. **Columns for fields that are filtered, sorted, joined or constrained; JSONB for nested contract objects.** `documents.payload` holds `author, links, media, screenshots, blocks, scrape_meta`; `findings` has JSONB `firm, advertiser, rules, model`. Matches §3 of the integration plan.
2. **One JSONB document per row.** Easiest to write, but no CHECK, foreign-key or unique constraints on contract fields, and every dashboard filter becomes a JSON path expression.
3. **Fully normalised** (`finding_rules`, `document_blocks`, `document_links` tables). Precise, but many inserts per document for data that is always read whole, and more migrations whenever a provisional field changes.

## Decision

- **Driver: psycopg 3** (option 1) for Alembic and the API, through SQLAlchemy 2 Core.
- **Layout: columns plus JSONB** (option 1), with:
  - enums as `text` + CHECK constraints (values from `contracts/schemas/`), not Postgres ENUM types;
  - `documents` unique on `(source_id, content_hash) NULLS NOT DISTINCT WHERE content_hash IS NOT NULL`, and a nullable `stream_published_at` marker;
  - `findings` unique on `(document_id, module)`, with no `risk_level` column ([ADR 0305](0305-threshold-storage.md));
  - UUID primary keys generated by the producer, `timestamptz` everywhere.

Why:
- One driver serves both the sync migrations and the async API, which removes a second dependency to pin and audit (`pip-audit` runs on every dependency, root `CLAUDE.md`).
- Columns plus JSONB is what integration-plan §3 already describes, keeps the database enforcing the rules other teams rely on (dedup, one finding per module, contract enums) and leaves nested provisional fields (ADR 0301) changeable without a migration.
- CHECK constraints can be widened in one revision, while a Postgres ENUM value cannot be removed.

## Consequences

- The scraper inserts documents with `INSERT ... ON CONFLICT DO NOTHING` and marks them with `stream_published_at`; analytics upserts findings with `ON CONFLICT (document_id, module) DO UPDATE`, leaving `status` and `note`. The exact SQL is in `api/README.md` once `api-db-schema` is applied.
- A new contract field nested in a JSONB column needs no migration; a new filterable field or enum value does (a new Alembic revision, reviewed by Damian).
- JSONB contents are not validated by the database: producers validate against `contracts/` before insert.
- Scraper and analytics may use any Postgres driver; only the API and Alembic are bound to psycopg 3.
