# Status: dashboard

Covers `web/` and `infra/`; whoever changes them updates this file (owners: [`.github/CODEOWNERS`](../../.github/CODEOWNERS)). Last updated: 2026-11-22 (Sun).

## State

- Foundation: app shell, RTK Query client generated from `contracts/openapi.yaml`, hardened container.
- Data from the backend only: browser mock mode removed, MSW only in Vitest ([ADR 0206](../decisions/0206-dashboard-data-from-backend.md)); `npm run dev` needs the contract mock server or the api on `API_PROXY_TARGET` (default `http://localhost:8000`).
- Root compose with Postgres + HTTPS gateway (`infra/`).
- Recharts installed ([ADR 0203](../decisions/0203-dashboard-charts-recharts.md)) with the trend chart (`web/src/features/trend/`): hour/day switch on `GET /stats/trend`, data table as text alternative, lazy-loaded (main bundle about 122 kB gzip with socket.io-client; Recharts in a shared 105 kB chunk used by the trend and calibration sections). jsdom needs a fixed chart size or a `ResizeObserver` stub (verified).
- Findings workspace (`web/src/features/findings/`, change `findings-explorer`): filters, sort and paging of `GET /findings` kept in the URL (no router, History API), risk as text plus colour, detail side panel on `?finding=<id>` with every `fail`/`uncertain` rule and its legal basis visible, screenshot preview, and status/note change via `PATCH /findings/{id}` (not optimistic; also invalidates `stats` through `src/api/enhanced.ts`). Checked against the contract mock server at 375, 768 and 1280 px. PR #39 review fixes (`findings-explorer-review-fixes`): focus kept on sort/pager during loading and inside the modal after a save (aria-disabled save button), detail in a portal with the page inert, two-step Escape, search keeps typed spaces, `react/exhaustive-deps` enabled.
- Real-time alerts (`web/src/features/alerts/`, change `realtime-alerts`, [ADR 0208](../decisions/0208-dashboard-realtime-socketio-client.md)): one Socket.IO connection to `/events`, refetch on connect, `finding.created`/`high_risk` invalidate findings and stats, `finding.updated` patches the cached status, high-risk toasts with `Pokaż`, and a live badge in the header. Checked in headless Chrome against the mock server (dev and production build, console clean in the build).
- Calibration panel (`web/src/features/calibration/`, change `calibration-panel`): module switch, a slider over the points of `GET /calibration` with TP/FP/FN/TN, precision, recall and F1 next to their values at the current threshold, a precision/recall chart (Recharts, lazy chunk shared with the trend) with a data table, and an explicit global `Zapisz próg` (`PUT /settings/thresholds`, which also invalidates findings, stats and calibration). Demo checked on the mock: M2 0.50 to 0.90 drops "Wysokie ryzyko" from 6 to 4 and recomputes the rows.
- Untrusted finding text (change `untrusted-text-plain`, issue #54): model explanations, evidence, summary, title, advertiser name/handle, excerpt and full text are plain React text, each alone in a `dir="auto"` element (a bidi isolate), in the table, the detail and the high-risk toast; tests pin `<img onerror>`, Markdown `javascript:` links, bare URLs and U+202E. Change `bidi-isolate-sr-text` (issue #99) covers the strings that have no element: the toast and close-button `aria-label`s and the live announcement wrap the title with `isolate()` (`web/src/format/bidi.ts`: FSI ... PDI, balanced so the title cannot close the isolate), and the server's error detail in the status editor has `dir="auto"`.
- One post, several modules (change `findings-same-document`, issue #33): each findings row shows the source host as text under the title (http(s) only) and stays one row per finding with its own status. The detail loads the findings of its document (`GET /findings?document_id=…`, contracts 1.1.0, no list filters) and, when there is more than one, shows a module switcher (`M1 · M3` with risk as text) above the module part; switching sets `finding=<id>` (deep link and back button work) and keeps focus on the switcher. A failed sibling request only hides the switcher. Not yet checked visually at 375/1280 px (no headless browser in the agent run).
- Untrusted finding text (change `untrusted-text-plain`, issue #54): model explanations, evidence, summary, title, advertiser name/handle, excerpt and full text are plain React text, each alone in a `dir="auto"` element (a bidi isolate), in the table, the detail and the high-risk toast; tests pin `<img onerror>`, Markdown `javascript:` links, bare URLs and U+202E.
- Evidence pack export (change `finding-export-button`, issue #70): the detail header has an `Eksportuj` link to `GET /findings/{id}/export?format=html` (contracts 1.2.0) under `VITE_API_BASE_URL`, opened in a new tab, so it works through the dev proxy (mock server since #109, or the api) and the gateway. Shown only for a loaded detail. The contract snapshot and `generated.ts` were regenerated for 1.2.0; the generated export query is unused (the page is a navigation).
- Re-scan state in the finding detail (change `web-rescan-state-badge`, web part of issue #71): `RescanNotice` under the source link shows `Zmieniona` (with the newer version's document id) or `Usunięta`, plus the check time in UTC, from the api's `document.scrape_meta.rescan`. `parseRescan` (`web/src/features/findings/data/rescan.ts`) treats `scrape_meta` as untrusted: only `changed`/`removed`, a UUID id and an ISO time get through; a missing key (contract mock), `current` or anything unknown shows nothing. No badge on the list (needs a `Finding` field, a contract change).
- Test timing (issue #60): the `web` image build runs lint and `vite build` only; the Vitest suite runs in CI and locally (opt in to the image with `--build-arg WEB_RUN_TESTS=1`). Vitest `testTimeout` is 20 s and Testing Library's `findBy`/`waitFor` default is 5 s (`web/src/test/setup.ts`), so a loaded machine does not turn slow renders into failures.
- Test isolation (issue #94): the shared `afterEach` in `web/src/test/setup.ts` awaits every RTK Query request still running in a test store (`makeStore`/`storeWrapper`, tracked in `web/src/test/inflight.ts`) before it resets the MSW handlers, so a request one test leaves in flight is never answered or counted by the next test's handlers.
- Hand-in package (issue #77, docs only): dashboard and architecture slides with the demo flow and video script in [presentation-dashboard.md](../presentation-dashboard.md); title, PL/EN description, PDF slide order and the human checklist in [hand-in.md](../hand-in.md). The demo flow is from the code and the mock, not yet rehearsed on real data (#78).
- Web rules in `.claude/rules/web-dashboard.md`.
- `iw-watch --mine` also sends an `approved` notice once per head sha when GitHub's review decision is APPROVED, no check failed, there is no conflict, the PR is not a draft and its base is the default branch; it never takes a `run --limit` slot (#105). The Discord notifier pings `IWATCH_DISCORD_USER_ID` with "your PR is approved! You can merge it now". No agent session, no merge.
- `iw-watch run` checks for a git identity first (`git var GIT_AUTHOR_IDENT` / `GIT_COMMITTER_IDENT` outside any repository, as a fresh clone sees it) and exits 2 with setup guidance without one, before any GitHub call or agent session (#127). A headless run on a machine without a global identity used to fail only at the merge commit, after the session.
